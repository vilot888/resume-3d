Python 数据处理与 AI 辅助系统

Python · 数据处理

把来源不一、格式不齐的数据整理成可复用结构，重点在清洗规则、异常拦截和可重复执行的流程。

  • 统一 CSV / Excel / JSON 多源输入到同一字段模型，落库前先过校验层，字段缺失与类型冲突在下游报错之前就被拦下
  • 把清洗规则抽成配置项，新增数据源只改配置、不动主流程；异常样本单独落盘并记录原因，便于回溯
  • 将重复的核对与汇总任务脚本化，按需一键重跑，替代人工反复整理
  • 流程内置去重、范围校验与空值策略，输出结果可直接进入后续分析

Java 业务模块开发

Java · 面向对象

承担业务模块的设计与实现，关注职责拆分、接口组织和后续可维护性。

  • 按职责划分包与模块，公共能力下沉为可复用组件，避免业务判断都堆在入口层
  • 梳理核心数据流转与状态变更路径，把散落在各处的判断收敛到明确的状态处理位置
  • 接口先行地建模业务实体与行为，方便替换实现、单独测试
  • 对常见故障形成固定排查顺序（日志定位 → 入参校验 → 数据状态核对），不只停在"功能能跑"

C++ 基础程序与算法实现

C++ · 算法

用 C++ 完成基础程序与算法实现，先保证正确性，再关注资源使用与结构清晰。

  • 独立完成基础开发任务，先覆盖边界条件，再谈实现方式
  • 理解指针、引用与对象生命周期，主动规避悬空指针、数组越界与资源未释放
  • 在规模可控的场景做过实现层面的优化（减少重复遍历、避免无谓拷贝）
  • 能把算法思路翻译成可运行代码，并配最小可复现用例自检

人工智能技术应用探索项目

Python · AI 应用

围绕「模型能解什么、工程怎么接」做的落地探索。

  • 梳理模型的能力边界与典型失败模式，明确哪些环节该交给模型、哪些该由规则与人工兜底
  • 用 Python 完成调用侧封装：入参组织、超时重试、返回结构解析
  • 对模型输出做结构化校验与兜底（格式校验、缺字段处理、失败重试），避免脏结果流入业务
  • 把 AI 需求拆成「模型能不能解」和「工程怎么接」两层分别评估，再决定技术方案

综合开发与应用实践

Python · Java · C++

在同一批任务里组合多种语言与方向，按场景选型。

  • Python 负责快速实现、数据处理与脚本工具，缩短验证想法的时间
  • Java 负责偏业务、需要结构化的部分，便于长期维护与扩展
  • C++ 负责对性能或底层理解要求更高的部分
  • 按场景在三种语言之间切换，不把一种思路套到所有问题上
